# Уровень решения проблемы обработки и генерации естественного языка, ч.5

Расширение семантического анализатора **Лабораторной работы 4** (CNN/GRU на
PyTorch) средствами **генерации осмысленного текста только на его основе**.
Генератор не использует внешних предобученных языковых моделей и сетевых API:
корпус, темы, словарь и представления документов берутся у анализатора `lab_4`,
а LSTM-языковая модель и sequence-to-sequence обучаются с нуля на этом же
корпусе. Реализованы:

1. **LSTM-языковая модель**, обусловленная темой анализатора (эмбеддинг темы
   конкатенируется с эмбеддингом слова на каждом шаге);
2. **sequence-to-sequence** — LSTM-энкодер → LSTM-декодер с аддитивным
   вниманием Багданау; две задачи: `документ → первый абзац` (реферирование) и
   `предложение → следующее предложение` (продолжение); тема подаётся и в
   энкодер, и в декодер;
3. **шаблонный генератор** (разрешён условием) — заполняет шаблоны только
   результатами анализатора: темой, ключевыми понятиями и ближайшим фрагментом
   корпуса;
4. **гибридное ранжирование** — кандидаты LSTM/seq2seq/шаблонов оцениваются по
   семантической близости (векторы `lab_4`), уверенности классификатора темы,
   «гладкости» LSTM, связности с корпусом, уникальности и завершённости фразы;
5. **n-граммные ограничения декодирования** — следующий токен выбирается только
   из переходов, встречавшихся в предложениях корпуса анализатора (сначала
   триграмма, затем биграмма). Это резко повышает связность LSTM/seq2seq на
   малом корпусе;
6. **сводка четырёх анализаторов** `SemanticSuite` — Байес (`lab_1`), LSA
   (`lab_2`), Doc2Vec (`lab_3`) и CNN/GRU (`lab_4`) на одних и тех же запросах,
   включая пользовательский корпус.

> **Основной файл лабораторной работы — [`notebooks/lab_5.ipynb`](notebooks/lab_5.ipynb).**
> Он отражает весь ход решения: данные, семантическое ядро `lab_4`, обучение
> LSTM-модели и двух seq2seq-моделей, кривые потерь, генерацию всеми режимами,
> шаблоны, гибридное ранжирование, сравнение четырёх анализаторов, пользовательский
> корпус и масштабный пример на отзывах RuReviews. Все источники случайности
> фиксируются `seed` (по умолчанию `42`), обучение идёт на CPU.

## Что умеет генератор

| Режим | Что делает | На чём основан |
| --- | --- | --- |
| `template` | связный текст из темы, ключевых понятий и лучшего предложения корпуса | `predict`, `query`, `doc_vector` анализатора |
| `lstm` | продолжает запрос LSTM-языковой моделью, обусловленной темой | корпус и темы `lab_4`; LSTM с эмбеддингом темы |
| `seq2seq` | порождает следующее предложение (или реферат документа) LSTM-энкодером/декодером | корпус, темы и пары предложений `lab_4` |
| `hybrid` | собирает кандидатов всех режимов и выбирает лучшего по 6 признакам | все представления и классификатор `lab_4` |

Дополнительно: `summarize(text)` — seq2seq-реферирование, `continue_text(prompt)` —
продолжение с возвратом запроса, `evaluate(text)` — разбор оценки по компонентам,
`candidates` в `Generation` — все кандидаты с оценками (удобно для анализа).

## Быстрый старт: генератор текста

```python
from lab_5.src import GeneratingAnalyzer

# 1) загрузка готовой модели (демо-корпус lab_2: 42 документа, 6 тем)
generator = GeneratingAnalyzer("lab_5/src/models/gen_cnn_demo", semantic_method="cnn")
print(generator.topics, generator.n_docs, generator.n_features)
# ['finance', 'food', 'health', 'sport', 'tech', 'travel'] 42 923

# 2) шаблонный режим: тема + ключевые понятия + лучшее предложение корпуса
print(generator.generate("футбольный матч и тренировка команды",
                         topic="sport", method="template").text)
# В корпусе тема «sport» описывается словами матч, команда и болельщик.
# Футбольный матч собрал полный стадион, и болельщики поддерживали свою команду
# с первой минуты.

# 3) LSTM-продолжение (тема обусловливает генерацию)
print(generator.generate("футбольный матч и тренировка команды",
                         topic="sport", method="lstm", seed=7,
                         max_words=20, min_words=6).text)
# Помогает футболистам справляться с волнением перед важным.

# 4) seq2seq: следующее предложение
print(generator.generate("футбольный матч и тренировка команды",
                         topic="sport", method="seq2seq", seed=7,
                         max_words=20, min_words=6).text)
# Тренер разбил команду на группы и предложил отрабатывать.

# 5) гибридный режим: лучший кандидат по шести признакам
result = generator.generate("как приготовить вкусный суп из овощей",
                            topic="food", method="hybrid", seed=7,
                            max_words=20, min_words=6)
print(result.text, round(result.score, 3))
# Морковь и лук обжаривают затем добавляют бульон и варят. 0.774
for candidate in result.candidates[:4]:
    print(candidate.method, round(candidate.score, 3),
          round(candidate.semantic, 3), round(candidate.topic_confidence, 3),
          round(candidate.coherence, 3))
# seq2seq 0.774 0.739 0.775 1.0
# template 0.75 0.754 0.786 1.0
# template 0.739 0.754 0.763 1.0
# seq2seq 0.696 0.678 0.494 1.0
```

### Обучение на своём корпусе

```python
import glob
from pathlib import Path
from lab_5.src import GeneratingAnalyzer, load_text_files

paths = sorted(glob.glob("lab_2/data/sample_docs/*.txt"))   # или свои .txt
texts = load_text_files(paths)
names = [Path(p).name for p in paths]

generator = GeneratingAnalyzer("lab_5/src/models/my_generator", semantic_method="cnn")
stats = generator.fit(
    texts, sources=names,                 # темы выводятся из префиксов имён файлов
    semantic_epochs=40,                   # обучение ядра lab_4
    epochs=80, seq2seq_epochs=80,         # LSTM и seq2seq
    embedding_dim=64, hidden_dim=96, num_layers=2, topic_dim=16,
    max_len=24, seq2seq_hidden_dim=64,
    batch_size=8, seed=42,
)
# n_docs=42, n_features=923, n_classes=6, dim=192, semantic_accuracy=1.0,
# lm_loss=0.859, lm_perplexity=2.36, lm_token_accuracy=0.903,
# lead_pairs=42, next_pairs=84, lead_loss=1.303, next_loss=0.848
```

`fit` требует **минимум две темы**: явные `labels` или имена файлов вида
`<тема>_<номер>.txt`. Обучение сохраняет всё в каталог модели
(`meta.json`, `weights.pt`, `corpus.json`, `semantic/`) — повторный запуск
загружает модель без переобучения.

> Модель `gen_cnn_demo` обучена командами из ноутбука (40 эпох ядра, 80 эпох
> LSTM/seq2seq), `gen_cnn_custom` — 60/100/100 эпох. Числа в примерах выше
> воспроизводятся при `seed=42`; при сэмплировании важен и `seed` генерации.

## Как генерация связана с анализатором `lab_4`

```
документы ──► NeuralAnalyzer (CNN/GRU, lab_4) ──► темы, doc_vector, predict, query
                    │
                    ├──► предложения (sent_tokenize lab_1) + словоформы (raw)
                    │        ├── LSTM-языковая модель (тема + слово)
                    │        └── seq2seq lead/next (LSTM-энкодер → LSTM-декодер + внимание)
                    │
                    └──► шаблонный генератор (тема + ключевые понятия + фрагмент корпуса)
                                 │
                                 ▼
                    n-граммные ограничения + гибридное ранжирование
                                 │
                                 ▼
                         осмысленный текст
```

* **Корпус и темы** — те же документы и метки, на которых обучен `lab_4`.
* **Словарь генератора** — словоформы (`doc_tokens(text, "raw")`), чтобы текст
  был читаемым; анализатор внутри по-прежнему работает с каноническими леммами.
* **Темы** — классы `lab_4`; номер темы подаётся в LSTM и в seq2seq.
* **Оценка кандидатов** — `doc_vector`/`predict`/`query` того же `lab_4`:
  семантическая близость к запросу, уверенность темы, близость к центроиду.
* **Ограничения декодирования** — биграммы/триграммы предложений корпуса
  анализатора, а не внешнего текста.

Никаких `transformers`, внешних чекпойнтов или обращений к сети нет.

### 1. Наивный Байес (`lab_1`, класс `SentimentAnalyzer`)

Это анализатор **тональности**, а не поиска по темам; он включён как первый
полученный анализатор естественного языка.

```python
from lab_5.src import SentimentAnalyzer

nb = SentimentAnalyzer("lab_1/src/models/sentiment_model.json")
for text in ["Отличный товар, очень доволен, рекомендую!",
             "Ужасное качество, всё сломалось через неделю.",
             "Обычный товар, ничего особенного."]:
    result = nb.analyze(text)
    print(result.label, {k: round(v, 3) for k, v in result.probabilities.items()})
# positive {'negative': 0.036, 'neutral': 0.009, 'positive': 0.955}
# neutral {'negative': 0.141, 'neutral': 0.453, 'positive': 0.407}
```

### Сводная таблица по шести запросам (демо-корпус)

`label` для CNN/GRU — предсказание классификатора, для LSA/Doc2Vec — тема
ближайшего документа, для Байеса — тональность.

| Запрос | Байес | LSA | Doc2Vec | CNN | GRU |
| --- | --- | --- | --- | --- | --- |
| Футбольный матч и тренировка команды на стадионе | negative | sport | sport | sport | sport |
| Новый ноутбук с мощным процессором и большим экраном | neutral | tech | tech | tech | tech |
| Как приготовить вкусный суп из свежих овощей | negative | food | health | food | tech |
| Пациент жалуется на боль и слабость, нужен осмотр врача | negative | health | health | health | health |
| Туристы забронировали номер и купили билеты на поезд заранее | negative | travel | travel | travel | tech |
| Он вложил сбережения, чтобы получить прибыль через год | negative | finance | finance | tech | health |

Согласие с LSA (опорным анализатором по темам): **Doc2Vec 5/6, CNN 5/6,
GRU 3/6**. Байес решает другую задачу (тональность), поэтому в согласие по
темам не входит; на нейтральных и предметных запросах он часто даёт `negative`
из-за смещения обучающего корпуса отзывов.

`SemanticSuite` не переобучает анализаторы: он загружает готовые модели и
приводит результаты к единому `AnalyzerView` (тема, вероятности, top-документы,
пояснение задачи). Если модель недоступна, это не исключение, а запись с
текстом в `note`/`errors`.

## Пользовательские данные

В репозитории есть «пользовательский» корпус
`lab_2/data/custom_corpus/` — 20 документов по 4 темам (auto, edu, fashion,

```python
from lab_5.src import GeneratingAnalyzer

custom = GeneratingAnalyzer("lab_5/src/models/gen_cnn_custom", semantic_method="cnn")
for prompt, topic in [
```

## Сравнительное описание четырёх анализаторов

| Критерий | Байес (`lab_1`) | LSA (`lab_2`) | Doc2Vec (`lab_3`) | CNN/GRU (`lab_4`) |
| --- | --- | --- | --- | --- |
| Задача | тональность: negative/neutral/positive | поиск по темам | поиск по темам + семантика слов | тема + поиск + классификация |
| Представление | мешок канонических лемм | TF-IDF + усечённый SVD | вектор документа PV-DBOW | max-pool свёрток / скрытые состояния GRU |
| Метод | мультиномиальный наивный Байес (с нуля) | матричное разложение (SVD) | shallow-сеть, SGD, negative sampling | свёрточная/рекуррентная сеть, SGD |
| Супервизия | да (тональность) | нет | нет | да (тема документа) |
| Размерность | словарь (≈3.3 тыс.) | `k` тем (10) | `dim` (100) | 192 (CNN) / 128 (GRU) |
| Объяснимость | высокая: вклад слов | высокая: тема = список терминов | средняя: ближайшие слова/документы | средняя: ближайшие слова, вероятности тем |
| Скорость обучения | очень быстрая | очень быстрая, детерминированная | средняя | ~2 c (CNN) / ~6 c (GRU) на демо |
| Что даёт | тональность отзыва | объяснимые темы, точные косинусы | семантику слов и документов | тему + обучаемое представление |
| Новый документ | канонические токены | fold-in проекцией | fold-in (`infer_vector`) | `encode` (CNN/GRU) |
| Ограничение | не ищет темы; чувствителен к смещению корпуса | не учитывает порядок слов | не учитывает порядок слов | данных нужно больше; CNN — фиксированное окно |

**Четыре анализатора — это четыре разных уровня проекта:** `lab_1` решает
тональность, `lab_2` — линейную семантику тем, `lab_3` — shallow-эмбеддинги,
`lab_4` — обучаемое нейросетевое представление с супервизией. `lab_5` ничего из
этого не заменяет: он **надстраивает генерацию** над `lab_4`, а остальные три
использует для сравнительного описания и сводки.

## Сравнительное описание генераторов

| Критерий | Шаблонный | LSTM-языковая модель | Sequence-to-sequence | Гибрид |
| --- | --- | --- | --- | --- |
| Основа | тема, ключевые понятия, фрагмент корпуса | тема + предыдущие слова | LSTM-энкодер → LSTM-декодер + внимание | все кандидаты + 6 признаков |
| Учитывает порядок слов | нет (цитата и шаблон) | да | да | да |
| Связность | гарантированная | высокая при n-граммных ограничениях | высокая при n-граммных ограничениях | максимальная из кандидатов |
| Новизна | низкая (по сути extractive) | средняя | средняя | зависит от победителя |
| Управление темой | явное | эмбеддинг темы | тема в энкодере и декодере | явное + классификатор |
| Скорость | мгновенно | быстро | быстро | медленнее (несколько кандидатов) |
| Риск | шаблонность, цитата | короткая/оборванная фраза | повторы, обрыв | выбирает лучшего, но дороже |

### Честная оценка качества

* **Шаблонный режим** даёт гарантированно грамматически связный и тематически
  точный текст, но он extractive: цитирует предложение корпуса. Это разрешено
  условием и полезно как baseline.
* **LSTM** после n-граммных ограничений выдаёт локально связные фразы
  («Процессор и экран с высокой яркостью», «Машина снова работает ровно и
  расход»), но на 42 документах часто обрывается на 4–8 словах.
* **Seq2seq** лучше всего работает как реферирование: на демо-корпусе он
  практически воспроизводит первое предложение документа (что ожидаемо при 42
  обучающих парах), на пользовательском корпусе и RuReviews — обобщает.
* **Гибрид** на демо-корпусе чаще выбирает шаблон или seq2seq, на
  пользовательском — seq2seq/шаблон; LSTM выигрывает реже. Это ожидаемое
  поведение: маленький корпус не даёт LSTM достаточно данных для свободной
  генерации.
* **Тематическая согласованность гибрида** на демо-корпусе — 6/6: текст,
  сгенерированный по каждой из шести тем без запроса, классификатор `lab_4`
  относит к той же теме (см. ноутбук).
* Ограничения честно видны в `Generation.candidates`: у каждого кандидата есть
  `semantic`, `topic_confidence`, `fluency`, `coherence`, `uniqueness`,
  `completeness`, поэтому решение гибрида можно объяснить, а не принимать на веру.

## Формат модели

Каталог модели (`src/models/gen_cnn_demo/`) состоит из трёх файлов и подкаталога
`semantic/`:

* `meta.json` — `version`, `semantic_method`, `n_docs`, `n_topics`, `topics`,
  `vocabulary` (индексы 0–3 — специальные токены, далее слова в
  лексикографическом порядке), `params` (все гиперпараметры) и `metrics`
  (потери, перплексия, точность, истории по эпохам);
* `weights.pt` — `torch.save({"lm": state_dict, "lead": state_dict|None,
  "next": state_dict|None})`;
* `corpus.json` — `{"texts": [...], "sources": [...], "labels": [...]}`;
* `semantic/` — каталог модели `lab_4` (`meta.json`, `weights.pt`, `docs.json`).

`GeneratingAnalyzer.load` проверяет `version == 1`, `semantic_method`, порядок
специальных токенов, `n_topics == len(topics)`, согласованность длин
`n_docs == len(texts) == len(sources) == len(labels)`, наличие обученного
семантического ядра и состояний `lm`; при нарушении — `ValueError` с текстом
«несовместимая версия модели, переобучите». Конструктор ловит это и возвращает
**необученный** экземпляр, положив ошибку в `load_error`.

```python
import json, shutil, tempfile
from lab_5.src import GeneratingAnalyzer

d = tempfile.mkdtemp()
for name in ("meta.json", "weights.pt", "corpus.json"):
    shutil.copy(f"lab_5/src/models/gen_cnn_demo/{name}", d)
meta = json.load(open(f"{d}/meta.json", encoding="utf-8"))
meta["version"] = 2
json.dump(meta, open(f"{d}/meta.json", "w", encoding="utf-8"), ensure_ascii=False)

broken = GeneratingAnalyzer(d)
print(broken.load_error)
# 'несовместимая версия модели, переобучите: version=2 в .../meta.json, ожидается 1'
```

смысл по каноническим леммам, генератор порождает поверхностные словоформы.

## Ограничения

1. Корпус демо-работы мал (42 документа, 126 предложений), поэтому свободная
   LSTM-генерация ограничена; основной выигрыш дают n-граммные ограничения и
   гибридное ранжирование.
2. Шаблонный режим extractive: он цитирует корпус, а не создаёт новое знание.
3. Seq2seq на демо-корпусе в режиме `lead` часто воспроизводит первое
   предложение; на больших корпусах (RuReviews) обобщение заметно лучше.
4. Метрики — обучающие; отдельного validation/test-разделения в работе нет.
5. Генератор не является диалоговой моделью: он продолжает/реферирует текст в
   стиле корпуса анализатора, а не отвечает на произвольные вопросы.
