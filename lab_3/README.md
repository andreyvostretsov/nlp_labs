# Уровень решения проблемы обработки и генерации естественного языка, ч.3


Расширение семантического анализатора **Лабораторной работы 2** 
новым методом сравнения набора документов на схожесть — **обучаемыми векторными
представлениями** (embeddings). Реализованы две **shallow-модели** на `numpy`:
**Word2Vec** (skip-gram, SGNS) обучает вектор слова предсказывать своё окружение, а
**Doc2Vec** (PV-DBOW) обучает вектор документа предсказывать слова этого документа;
обе — с **negative sampling**. Сверху построен фасад `DocVecAnalyzer` (обучение,
семантический поиск, близость документов, векторы слов), а сам анализ сравнивается
с LSA-анализатором `SemanticAnalyzer` на одних и тех же запросах.

> **Основной файл лабораторной работы — [`notebooks/lab_3.ipynb`](notebooks/lab_3.ipynb).**
> Он отражает весь ход решения: данные, нормализацию из `lab_1`, Word2Vec (skip-gram,
> SGNS), Doc2Vec (PV-DBOW), семантический поиск, близость документов и векторы слов,
> сравнение с LSA из `lab_2`, группировку документов и 2D-проекцию, пользовательский
> корпус и масштабный пример на отзывах RuReviews. Для воспроизводимости все
> источники случайности используют **локальный** `numpy.random.RandomState(seed)`
> внутри `fit` (по умолчанию `seed=42`), порядок обхода документов и лексикографический
> порядок словаря стабильны — глобальный `np.random.seed` не вызывается, и два `fit`
> с одинаковым `seed` дают одинаковые векторы.

## Что умеет анализатор

1. **Word2Vec** (skip-gram, SGNS) — векторы **слов**: для каждого слова-центра
   перебирается окно контекста радиуса `window`, положительная пара `(центр →
   контекст)` и `negative` негативов из unigram-распределения `count**0.75`;
2. **Doc2Vec** (PV-DBOW) — векторы **документов**: для каждого документа
   положительная пара `(документ → слово)` + негативы, обновляется вектор документа
   и выходные векторы слов;
3. **семантический поиск** — запрос векторизуется fold-in (`infer_vector` для
   Doc2Vec, mean-pooling для Word2Vec) и сравнивается по косинусной близости со
   всеми документами;
4. **близость документов** — ближайшие соседи документа в пространстве эмбеддингов;
5. **словесная семантика** (`most_similar`) — ближайшие слова к заданному; для OOV
   возвращается `[]`, а не исключение;
6. **сравнение с LSA** — тот же набор запросов прогоняется через `SemanticAnalyzer`
   из `lab_2` (модель загружается без переобучения) и сопоставляется по темам.

## Использование как библиотеки

Весь код работы — в пакете `lab_3` (каталог `./lab_3`); один импорт `lab_3.src`
даёт и новые модели, и `DocVecAnalyzer`, и LSA-анализатор из `lab_2`.

```python
import glob
from pathlib import Path
from lab_3.src import DocVecAnalyzer, SemanticAnalyzer, Word2Vec, Doc2Vec

# 1) обучение Doc2Vec на демо-корпусе (или на любом своём наборе .txt-файлов)
analyzer = DocVecAnalyzer("lab_3/src/models/d2v_demo")
paths = sorted(glob.glob("lab_2/data/sample_docs/*.txt"))
texts = [Path(p).read_text(encoding="utf-8").strip() for p in paths]
stats = analyzer.fit(texts, dim=100, epochs=40,
                     sources=[Path(p).name for p in paths], seed=42)
# stats: {'n_docs': 42, 'n_features': 666, 'dim': 100, 'epochs': 40,
#         'negative': 5, 'method': 'doc2vec', 'seconds': 2.45}

# 2) семантический поиск «своими словами»
for m in analyzer.query("Новый ноутбук с мощным процессором и большим экраном", top_n=2):
    print(round(m.score, 3), m.source, m.text[:50])
# 0.716 tech_01.txt Новый ноутбук получил быстрый процессор и экран...
# 0.413 tech_02.txt Процессор нового поколения содержит больше ядер...

# 3) близость документов и словесная семантика
analyzer.similar(0, top_n=6, exclude_self=True)   # соседи документа 0
analyzer.most_similar("матч", top_n=5)            # ближайшие слова (OOV → [])
```

После обучения модель сохраняется в каталог из трёх файлов (`meta.json`,
`vectors.npz`, `docs.json`), поэтому в следующий раз она загружается мгновенно:

```python
from lab_3.src import DocVecAnalyzer
analyzer = DocVecAnalyzer("lab_3/src/models/d2v_demo")   # уже обучена
analyzer.query("Футбольный матч и тренировка команды на стадионе")
```

Второй метод того же фасада — Word2Vec: `DocVecAnalyzer(path, method="word2vec")`
обучает skip-gram, а вектор документа получается mean-pooling'ом векторов его слов:

```python

### 1. Новый анализатор на демо-корпусе: `DocVecAnalyzer("lab_3/src/models/d2v_demo")`

Обучение: `fit(demo_texts, dim=100, epochs=40, sources=<имена файлов>, seed=42)`.

```

n_docs     = 42
n_features = 666
dim        = 100
epochs     = 40
negative   = 5
seconds    = 2.45
```

Семантический поиск по запросам «своими словами» (top-1 … top-3, косинус):

| Запрос | top-1 | top-2 | top-3 |
| --- | --- | --- | --- |
| «Футбольный матч и тренировка команды на стадионе» | `sport_02.txt` **+0.728** | `sport_06.txt` +0.566 | `sport_03.txt` +0.543 |
| «Как приготовить вкусный суп из свежих овощей» | `health_03.txt` **+0.427** | `tech_07.txt` +0.250 | `tech_01.txt` +0.211 |
| «Новый ноутбук с мощным процессором и большим экраном» | `tech_01.txt` **+0.716** | `tech_02.txt` +0.413 | `tech_07.txt` +0.276 |

Запросы не совпадают с текстами дословно — анализатор находит документы по смыслу.
Два запроса из трёх попадают в тему точно. Запрос про «суп» даёт слабый и

показывающий ограничение PV-DBOW на маленьком корпусе (42 коротких документа,
666 терминов): обучаемых параметров много, а данных мало.

#### Близость документов

`similar(0, top_n=6, exclude_self=True)` — документ `finance_01.txt`:

```
[+0.354] finance_07.txt   [+0.303] finance_05.txt   [+0.250] finance_06.txt
[+0.221] finance_03.txt   [+0.128] tech_01.txt      [+0.121] travel_06.txt
```

4 из 6 ближайших — своя тема `finance`: документы группируются по смыслу без

#### Словесная семантика (`most_similar`)

```
матч      -> тренер(+0.74), игра(+0.72), команда(+0.69), игрок(+0.66), вратарь(+0.52)
процессор -> поколение(+0.34), администратор(+0.29), быстрый(+0.29), охлаждение(+0.28)

### 2. Word2Vec-режим: векторы слов важнее документа

`Word2Vec(dim=60, epochs=15, seed=42).fit(demo_tokens)` — обучение **6.93 c**,
словарь **666** слов, `vectors_` формы `(666, 60)`:

```
матч      -> тренер(+0.72), игрок(+0.71), игра(+0.69), команда(+0.67), вратарь(+0.59)
процессор -> быстрый(+0.42), тормозить(+0.39), содержать(+0.38), высокий(+0.35), оставить(+0.34)
футбол    -> нет в словаре (OOV); most_similar -> [] (метод не падает)
```

То есть на уровне **слов** skip-gram даёт ту же спортивную группу, что и Doc2Vec;
арифметика векторов (`a − b + c`) на словаре из 666 терминов работает неустойчиво —
ожидаемое ограничение объёма данных, а не ошибка метода.

Для полноты: Doc2Vec с `dim=60, epochs=40` обучается за **2.04 c** и даёт
`doc_vectors_` формы `(42, 60)` и `word_vectors_` формы `(666, 60)`; fold-in
запроса возвращает вектор формы `(60,)` с L2-нормой `1.587`.

метки (префикс имени файла до `_`).

| Запрос | LSA top-1 | Doc2Vec top-1 | Jaccard top-3 |
| --- | --- | --- | --- |
| Игроки вышли на поле и боролись за победу в важном турнире | sport | sport | 1.00 |
| Мама положила в кастрюлю овощи и поставила на плиту готовиться обед | food | sport | 0.00 |

| Туристы забронировали номер и купили билеты на поезд заранее | travel | travel | 1.00 |
| Пациент жалуется на боль и слабость, нужен осмотр врача | health | health | 1.00 |
| Он вложил сбережения, чтобы получить прибыль через год | finance | finance | 1.00 |

## Сравнительное описание анализаторов

Три представления — **LSA** (`lab_2`, класс `SemanticAnalyzer`), **Word2Vec**
(skip-gram, класс `Word2Vec`) и **Doc2Vec** (PV-DBOW, класс `Doc2Vec`) — устроены
принципиально по-разному:

| Критерий | LSA (`lab_2`) | Word2Vec (skip-gram) | Doc2Vec (PV-DBOW) |
| --- | --- | --- | --- |
| Представление документа | TF-IDF + усечённое SVD (латентные темы) | mean-pooling векторов слов документа | собственный вектор документа |
| Математический метод | матричное разложение (SVD, линейная алгебра) | shallow-сеть, SGD, negative sampling | shallow-сеть, SGD, negative sampling |
| Размерность | `k` тем (обычно 10–40) | `dim` (60–100) | `dim` (60–100) |
| Интерпретируемость | высокая: тема = список терминов | средняя: ближайшие слова | средняя: ближайшие слова/документы |
| Скорость обучения | быстрое, детерминированное (0.003 c на демо) | медленнее, зависит от эпох (6.93 c на демо) | медленнее, зависит от эпох (2.45 c на демо) |
| Что даёт | объяснимые темы, точные косинусы на малых корпусах | семантику **слов**, аналогии | вектор **всего документа**, устойчивость к перефразировке |
| Новый документ | fold-in проекцией | mean-pooling векторов слов | fold-in (`infer_vector`) |
| Ограничение | не учитывает порядок и контекст | нет вектора документа напрямую | на малом корпусе нестабилен |

**Ни одна из трёх моделей не использует CNN/RNN/LSTM.** LSA — это чистая линейная
алгебра: TF-IDF-матрица раскладывается усечённым сингулярным разложением
`X ≈ U·S·Vᵀ`, документы проецируются как `X·Vᵀ`. Word2Vec — **skip-gram**:
однослойная модель, которая по вектору слова предсказывает слова своего окружения.
Doc2Vec — **PV-DBOW**: такая же однослойная модель, но по вектору **документа**
предсказываются слова этого документа. Обе обучаемые модели используют **negative
sampling** (SGNS) и обновляются SGD по формуле `g = lr·(label − σ(v_in·v_out))`;
это shallow-модели без скрытых нелинейных слоёв, свёрток и рекуррентности.

На практике на малом демо-корпусе (42 документа) методы дают близкий результат:
**top-1 agreement 0.833**, **средний Jaccard top-3 0.833**, а расходится только
один запрос («овощи/суп»). При этом LSA даёт более «уверенные» косинусы (0.89–0.98
против 0.43–0.73 у Doc2Vec) и объяснимые темы, тогда как Word2Vec/Doc2Vec выигрывают
там, где нужна семантика **слов** (`матч → тренер, игра, команда, игрок, вратарь`)
и масштабирование на корпус без разметки (2000 отзывов RuReviews за 12.1 c). Выбор
метода — компромисс между объяснимостью и обучаемым представлением; в этой работе
оба анализатора доступны из одного пакета и работают на одних и тех же канонических
токенах `lab_1`, поэтому сравнение корректно.

## Источник данных и переиспользование lab_1 и lab_2

- **Демо-корпус** `../lab_2/data/sample_docs/` — 42 коротких русских документа по
  6 темам (finance 7, food 7, health 7, sport 7, tech 7, travel 7).
- **Пользовательский корпус** `../lab_2/data/custom_corpus/` — 20 документов по
  4 темам (auto 5, edu 5, fashion 5, music 5).
- **RuReviews** ([Smetanin & Komarov, 2019](https://ieeexplore.ieee.org/document/8807792),
  Apache 2.0) переиспользуется из `lab_1` — тексты загружаются через
  `lab_3.src.load_reviews`, который делегирует в загрузчик `lab_1`.

Код работы целиком лежит в каталоге **`./lab_3`** и **не дублирует** предыдущие
лабораторные:

- нормализация (токенизация, стемминг Snowball, лемматизация pymorphy3, синонимия,
  стоп-слова) делегируется в `lab_1` через мост `lab_3/src/_lab1.py`;
- LSA-анализатор `SemanticAnalyzer`, косинусная близость и загрузчики корпусов
  (`load_text_files`, `load_lines`, `load_reviews`, `doc_tokens`) делегируются в
  `lab_2` через мост `lab_3/src/_lab2.py`;
- оба моста — тонкие реэкспорты, **код `lab_1` и `lab_2` не модифицируется**.

Токенизация для моделей — `doc_tokens(text, "canonical")` (лемма + синонимы без
стоп-слов), то есть **те же канонические токены**, что и у LSA в `lab_2`: различие
результатов объясняется моделью, а не разной предобработкой. На демо-корпусе
размер словаря в канонических токенах — **666**; доступен и режим `mode="raw"`
(только нижний регистр).

## Формат модели

Каталог модели (например `src/models/d2v_demo/`) состоит из **трёх файлов**:

- `meta.json` — `version`, `method` (`doc2vec`/`word2vec`), `dim`, `n_docs`,
  `vocabulary` (список терминов в лексикографическом порядке) и `params`
  (`epochs`, `negative`, `min_count`, `window`, `mode`, `seed`, `alpha`, `min_alpha`);
- `vectors.npz` — три массива: `doc_vectors` (`n_docs × dim`, float32),
  `word_vectors` (`len(vocabulary) × dim`, float32, выходной слой слов) и
  `word_counts` (`len(vocabulary)`, int64 — частоты токенов, нужны `infer_vector`
  для unigram-распределения негативов);
- `docs.json` — `{"texts": [...], "sources": [...]}` (тексты документов для
  сниппетов и их источники).

`DocVecAnalyzer.load` (и конструктор) проверяет `version == 1` и согласованность
длин (`len(vocabulary) == word_vectors.shape[0] == word_counts.shape[0]`,
`n_docs == doc_vectors.shape[0] == len(texts)`); при несовпадении — `ValueError` с
текстом «несовместимая версия модели, переобучите». Конструктор ловит это
`ValueError` и возвращает **необученный** экземпляр, положив текст ошибки в
атрибут `load_error`:

```python
import json, shutil, tempfile
from lab_3.src import DocVecAnalyzer

d = tempfile.mkdtemp()                                  # копия модели с чужим version
for f in ("meta.json", "vectors.npz", "docs.json"):
    shutil.copy(f"lab_3/src/models/d2v_demo/{f}", d)
meta = json.load(open(f"{d}/meta.json", encoding="utf-8"))
meta["version"] = 2
json.dump(meta, open(f"{d}/meta.json", "w", encoding="utf-8"), ensure_ascii=False)

broken = DocVecAnalyzer(d)
print(broken.load_error)
# 'несовместимая версия модели, переобучите: version=2 в .../meta.json, ожидается 1'
```

Если каталога модели нет вовсе, исключения тоже не возникает: возвращается
необученный анализатор (`load_error is None`), а любое обращение к модели до
`fit`/`load` поднимает `RuntimeError` с сообщением «модель не обучена — вызовите
`fit(...)` или выполните ноутбук». После успешного `load` внутренняя модель
(`Doc2Vec`/`Word2Vec`) восстанавливается целиком, поэтому `query`, `similar`,
`most_similar`, `word_vector` и `doc_vector` работают без повторного обучения.
